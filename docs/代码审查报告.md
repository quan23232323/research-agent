## 二、必须修复（P1）

### P1-1 前端 XSS：用户输入与报告正文未转义直插 innerHTML

**位置**：`frontend/js/app.js:346`、`:603`、`:311`

```js
// :603 historyRow —— it.topic 是用户输入，未转义
tr.innerHTML = `... <td class="topic-cell" title="${it.topic}">${it.topic}</td> ...`;

// :346 renderSubqInfo —— 子问题同样未转义
return `<div class="subq-line ...">${sq}` + ...

// :311 renderTaskView —— 无 sanitize 渲染 LLM 产出
const body = window.marked ? marked.parse(result.report_md) : `<pre>...</pre>`;
$("#reportBody").innerHTML = body;
```

**为什么严重**：历史记录是全局共享的（无用户隔离），团队共用 `AUTH_TOKEN` 场景下这是**存储型 XSS**——
只要有人提交一个形如 `<img src=x onerror=...>` 的主题，任何打开历史页的人都会中招。
`marked.parse` 那条更隐蔽：报告正文来自 LLM 对**不可信网页**的摘录，恶意页面可以诱导模型回显脚本。

**修复**：
- `marked.parse` 结果过 DOMPurify 再插入，或给 marked 配置 sanitize；
- `topic` / 子问题一律用 `textContent` 赋值，不要拼进 innerHTML 模板。

### P1-2 鉴权未覆盖 `/docs` 与 `/openapi.json`

**位置**：`backend/main.py:47` —— 中间件条件是 `path.startswith("/api/")`

**实测结果**（已用 TestClient 验证，`AUTH_TOKEN=secret-token`）：

```
/openapi.json    -> 200     ← 未授权即可读取完整接口契约
/docs            -> 200     ← Swagger UI 公开
/api/meta        -> 401     ← 只有 /api/* 被拦住
```

**修复**：生产环境关闭文档端点，或把 401 校验提到路径判断之前。

```python
app = FastAPI(..., docs_url=None, redoc_url=None, openapi_url=None)  # 生产
```

### P1-3 开启令牌后 SSE 实时流静默失效

**位置**：`frontend/js/app.js:176`

```js
const es = new EventSource(`/api/tasks/${taskId}/events`);   // 无法携带 X-API-Key 头
```

**后果**：`EventSource` 是浏览器原生 API，**不支持自定义请求头**。启用 `AUTH_TOKEN` 后该请求返回 401，
触发 `es.onerror` → `es.close()` → 降级到 `pollUntilDone()` 每 2 秒轮询状态。
也就是说 README 主打的「SSE 实时推送工具调用轨迹与流式撰写预览」在鉴权开启后**完全不可见**，
而用户界面不会有任何提示——这是功能真实性问题，比它看起来更严重。

**修复**（三选一）：
1. 用 `fetch` + `ReadableStream` 自行实现 SSE 解析（可带 Header），最优；
2. 后端为 SSE 单独签发一次性短时效 ticket 走 query 参数（不用主令牌）；
3. 至少在降级时给用户一个明确提示，不要让功能静默消失。

## 三、建议改进（P2）

| 问题 | 位置 | 说明与修法 |
| --- | --- | --- |
| 限流在反向代理后失效且可绕过 | `main.py:53` | 用 `request.client.host`，Nginx 后拿到的是代理 IP → 所有用户共用一个桶。且 key 含 `path`（带 task_id），换 task 即换桶。修法：读 `X-Forwarded-For`（需 uvicorn `--proxy-headers --forwarded-allow-ips`），限流 key 去掉 path |
| 后台任务弱引用 | `routes.py:117` | `create_task(run_task(...))` 返回值未保存，asyncio 只持弱引用，极端情况下任务可能被 GC 中断（`RUNNING` 存的是 id 字符串，不是 Task 对象）。修法：模块级 `_BG: set` + `add_done_callback(discard)` |
| 删除任务不清理版本快照 | `storage.py:182` | `delete()` 只删 `tasks` 行，`report_versions` 里的快照成孤儿，DB 无限增长 |
| 重写失败仍产生版本快照 | `routes.py:272` | `add_version` 在 `svc.rewrite` 之前调用，LLM 报 502 时会留下一条与实际内容相同的「伪版本」，污染版本列表 |

## 四、代码质量细节（P3）

- `writer._stream_write` 跨模块访问 `ctx.llm._client` **私有属性**，且流式路径不走 `fallback_models`、不调 `budget.check()`——预算硬顶在这里有缺口。
- `llm.chat` 重试循环在**最后一次尝试后仍然 sleep**（最多浪费约 2 秒），应加 `if attempt < 2`。
- `storage.py` 单连接 + 全局锁，且在异步路径里**同步写入大字段**（`report_md` + `materials` JSON），会阻塞事件循环。建议开启 `PRAGMA journal_mode=WAL`（未启用）。
- `Task.history` **无上限**；`chunk` 事件按 delta 逐条推送，长报告事件量可观。
- `validate_settings` 未校验 `reviewer_rewrite_limit` / `max_sources`；`config.yaml` 缺 key 时抛的是 `KeyError` 而非友好提示。
- `restoreVersion` 中硬编码 `renderTaskView("done", state.report)`，**partial 任务恢复后会显示「已完成」**（`backToLatest` 写法是对的，这里不一致）。
- CORS 默认 `*` 且 `CORSMiddleware` 位于鉴权中间件**内层**，导致 401 / 429 响应不带 CORS 头，跨域前端只会看到不透明的网络错误。
- 无 lint / 格式化 / 类型检查配置（ruff / black / mypy 均缺），CI 只跑 pytest + `node --check`。
- 并发上限检查与 `RUNNING.add()` 之间存在 TOCTOU 竞态。
