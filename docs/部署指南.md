# 部署指南（生产环境）

> 适用版本：v1.2.0+。三种部署方式按推荐度排序：Docker Compose > 裸机 + systemd > 直接运行。

## 1. Docker Compose（推荐）

```bash
cp .env.example .env          # 填入 LLM_API_KEY 等真实配置
docker compose up -d --build
curl http://127.0.0.1:8000/api/health
```

- `./reports` 卷：报告文件（md + html）
- `./data` 卷：SQLite 任务历史——**备份这两个目录即可完整备份服务数据**
- 健康检查：容器内每 30s 探测 `/api/health`，连续失败自动重启

更新版本：

```bash
git pull && docker compose up -d --build
```

> 国内拉取基础镜像失败时：`docker pull docker.m.daocloud.io/library/python:3.12-slim && docker tag docker.m.daocloud.io/library/python:3.12-slim python:3.12-slim`

## 2. Nginx 反向代理（HTTPS 上线）

```nginx
server {
    listen 443 ssl;
    server_name research.example.com;
    ssl_certificate     /etc/ssl/certs/research.pem;
    ssl_certificate_key /etc/ssl/private/research.key;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_buffering off;          # SSE 流式推送必需
        proxy_read_timeout 900s;      # 研究任务为分钟级长连接
    }
}
server {
    listen 80;
    server_name research.example.com;
    return 301 https://$host$request_uri;
}
```

**关键点**：`proxy_buffering off` 否则 SSE 进度会被 Nginx 缓冲，前端看不到实时进度；`proxy_read_timeout` 需大于单份报告的最长生成时间。

## 3. systemd 裸机部署

```ini
# /etc/systemd/system/research-agent.service
[Unit]
Description=Research Agent Service
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/research-agent
Environment="LLM_API_KEY=sk-xxx"
Environment="AUTH_TOKEN=change-me"
ExecStart=/opt/research-agent/.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now research-agent
```

> ⚠️ 任务状态在进程内存中，**必须 `--workers 1`**（多 worker 会导致任务状态分裂）；横向扩展需先引入 Redis 共享存储。

## 4. 环境变量参考

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `LLM_BASE_URL` | OpenAI 兼容接口地址 | `https://api.deepseek.com` |
| `LLM_API_KEY` | 模型 API Key（不填自动进入 Mock 模式） | 空 |
| `TAVILY_API_KEY` / `BOCHA_API_KEY` | L1 备用搜索源 | 空 |
| `AUTH_TOKEN` | API 令牌鉴权（非空启用；页面 ⚙ 设置中填同一令牌） | 空（关闭） |
| `ALLOW_ORIGINS` | CORS 来源，逗号分隔 | `*` |
| `LOG_LEVEL` | 日志级别 | `INFO` |
| `DATA_DIR` | SQLite 数据目录 | `./data` |
| `MOCK_LLM` / `MOCK_SEARCH` | 演示开关（1=Mock） | `0` |

`config.yaml` 控制模型分层档位、Token 预算、限流值、敏感词、并发与导出开关。

## 5. 安全清单（上线前自检）

- [ ] 设置 `AUTH_TOKEN`（或置于内网/VPN 之后）
- [ ] `ALLOW_ORIGINS` 收敛为具体域名
- [ ] 反向代理启用 HTTPS
- [ ] 检查 `config.yaml` 敏感词表是否符合业务合规要求
- [ ] 确认 `data/` 与 `reports/` 已纳入备份策略（含数据库写一致性：备份前停写或使用 `sqlite3 .backup`）

## 6. 备份与恢复

```bash
# 备份（推荐热备）
sqlite3 data/research.db ".backup 'backup/research-$(date +%F).db'"
cp -r reports/ backup/reports-$(date +%F)/

# 恢复：停服 -> 还原两个目录 -> 启动
```

## 7. 监控

- `GET /api/health`：存活 + 版本 + 运行中任务数（探活用）
- `GET /api/stats`：任务总量/成功率/累计 Token 与成本/平均耗时/运行时长
- 日志：标准输出，`LOG_LEVEL=INFO`，任务启动/完成/兜底触发均有结构化条目
